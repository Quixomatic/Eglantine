## Highlights

Brings in 57 commits from upstream Eglantine, mainly so OOT gets past its startup abort. Donkey Kong Bananza keeps its speed: the open map holds about 25 fps, and the view facing away from it the 60 fps cap.

- **OOT:** no longer aborts at startup.
- **Donkey Kong Bananza:** upstream's new wait for every frame is left out, because it cost about a quarter of the open map's fps.

Numbers are from one machine and one benchmark route, so expect different results on other hardware and in other games.

## New Features

- **From upstream Eglantine:** `WaitForAddress` arbitration type 3 (`WaitIfEqual64`), Phi nodes of more types in the SPIR-V backend, and the NUP update's display version in the game list tooltip.

## Improvements

- **The game's own DLSS runs wherever it can.** Upstream removed the "Use the game's own DLSS" setting. `EDEN_NX2_DLSS_REPLACEMENT` still asks for the replacement upscale.
- **Updated shared font data,** and conditional barriers on Intel's ANV driver.

## Fixes

- **OOT's startup abort:** the game's 64-bit address wait returned an error, and the game panicked before its first frame.
- **From upstream:** the H0_NH1 half source, the Polish language code, NUP fixes, and the subgroup size check for compute pipelines.

## Under the hood

Three upstream changes are not taken:

- **Donkey Kong Bananza's wait for every frame at present.** It is meant to stop freezes and rubberbanding, but it took the open map from 25.2 to 19.0 fps and the view away from it from 60 to 37. `EDEN_NX2_FRAMES_AHEAD=0` turns it on.
- **Mapped-size storage buffers on every native compute dispatch.** Only game DLSS passes use them, because upstream measured Hyrule Warriors falling from 42-57 fps to about 2 otherwise.
- **Upstream's new CI pipeline.** This fork keeps its own release workflow.

## Known issues

- Donkey Kong Bananza's 1% low is lower than in v0.1.32 in one run each (open map 22.9 to 20.8, facing away 55.2 to 51.0). It is not yet known whether this is real.
- If Donkey Kong Bananza freezes or rubberbands, `EDEN_NX2_FRAMES_AHEAD=0` is the first thing to try, at the fps cost above.
- The issues listed for v0.1.32 still apply.
